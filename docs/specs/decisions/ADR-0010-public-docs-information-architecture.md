# ADR-0010: Select PropertyでDocsを分類し、Dataリンクを閲覧先に応じて解決する

## Status

Proposed (2026-09-07)

PLT-4359。PR #309の閲覧専用UIを起点とする設計提案。#310にはこのADRとappbar・パンくずの表記修正を含む。Property選択設定、BlockNoteのDataリンク、リンク解決処理はまだ実装しない。

## Context

公開Repoのトップと左サイドバーは、現在、読み込み済みDataの一覧から生成される。記事をセクションに分け、トップや記事本文から他のDataへ案内できるようにしたい。

LibraryにはSelect Propertyと選択肢のID、DataのoptionIdがある。Docs専用のセクションと所属記事一覧を別管理すると、通常のData分類と二重管理になる。また、本文にLibraryの編集画面URLを直接保存すると、公開Docsからも編集画面へ遷移してしまう。

## Decision（提案）

**セクションは既存のSelect Propertyで管理し、Docs設定では分類に使うPropertyを選ぶ。本文にはDataへの参照を保存し、LibraryとDocsそれぞれの閲覧先に応じてリンクURLを解決する。**

### 1. セクションはPropertyの値から生成する

例として、通常のRepoにSelect Property「セクション」を用意する。

| Data | セクション（Select） |
| --- | --- |
| ようこそ | はじめに |
| クイックスタート | はじめに |
| 顧客を管理する | 基本操作 |
| 予約を確認する | 基本操作 |

Repo設定の「公開ドキュメント」で、このPropertyをセクション用として選択する。左サイドバーは選択肢を見出し、同じoptionIdを持つDataをその配下の記事として表示する。

```text
公開ドキュメント設定
  トップ用Data：［ようこそ ▼］
  セクション用Property：［セクション（Select）▼］

読者向けの左サイドバー
  トップ
  はじめに
    ようこそ
    クイックスタート
  基本操作
    顧客を管理する
    予約を確認する
```

- セクション名の変更や記事の分類は、既存のProperty設定とData編集で行う。
- セクション名は選択肢の表示名から取得する。Property IDとoptionIdを参照し、改名で所属を失わない。
- Docs独自のsections/dataIds配列や、記事をセクションへ再配置する専用編集UIは作らない。
- 初期対応は単一Selectとする。MultiSelectは複数セクションへの重複表示と前後移動の意味が変わるため、追加判断とする。
- 値が未設定、または削除済み選択肢を参照する記事は「その他の記事」に表示する。空のセクションは表示しない。
- セクション用Propertyを選ばないRepoは、従来の記事一覧を表示する。必須の専用Propertyは追加しない。
- 選択中のPropertyの削除・型変更時は通常一覧へ戻し、管理画面に再選択が必要と表示する。

セクション順は既存の選択肢順を利用する案とし、その順序を保存・取得できる契約をDDで確認する。記事順は初期段階では安定した既定順を用い、作成日時＋Data IDなどの具体的なキーをDDで定める。任意順が必要なら既存の並び順Propertyを選ぶ方式を検討し、Docs側で記事ID配列を二重管理しない。

### 2. トップもData本文で作る

トップ用Dataを1件選び、そのBlockNote本文をトップに表示する。紹介文、見出し、他の記事への案内は通常のData編集で作る。おすすめ記事は本文内のDataリンクで表現することを基本とし、独立したおすすめカード設定は設けない。カード風表示が必要な場合はDataリンクの表示形式として検討する。

トップ用Dataを選ばない場合は、Repo名・説明・記事一覧の自動トップを維持する。トップ用Dataの選択はそのDataの分類や記事URLを変更せず、サイドバー上の所属はProperty値に従う。トップ用Dataが削除された場合も自動トップへ戻す。

appbarとパンくずはRepo名を用い、「利用ガイド」など用途を限定する固定ラベルは付けない。トップ本文の大見出しは選択したDataのタイトルを使う。

### 3. BlockNoteでDataへのリンクを挿入する

Libraryの通常のBlockNote編集で、リンク先のDataを検索・選択して本文へ挿入できるようにする。Docs専用エディターは作らない。挿入操作の具体的なUIと、インライン参照かブロックかはDDで決める。

本文には編集画面URLやDocs URLを固定で保存せず、参照先のRepo・Dataを識別する情報を保存する。実際のBlockNote schema、既存リンクとの互換性、MarkdownやHTMLへの変換形式は実装前に確定する。

| 本文を表示する場所 | Dataリンクの解決先 |
| --- | --- |
| Libraryの通常画面 | 参照先Dataを開く既存のLibrary導線 |
| 公開Docs | 参照先の記事URL `/public/{organization}/{repository}/{dataId}` |

同じ本文をLibraryとDocsで共有し、表示時のコンテキストからURLを解決する。Docsでリンクを押すとDocsのまま記事を読むことができる。記事名は原則として参照先Data名を用い、参照キーは名前やslugではなく安定したIDとする。参照先Dataがトップ用でもリンクは記事URLへ解決し、トップ設定の変更で意味が変わらないようにする。

Dataリンクは一般の外部URLリンクと区別する。通常のリンクをすべて書き換えることや、保存済みの編集URLを文字列置換することはしない。既存本文は維持し、新しいData参照形式を追加する。

### 4. 公開範囲と参照解決

Selectによる分類やサイドバーへの掲載は公開権限ではない。public RepoのDataは従来どおり公開対象であり、未分類を非公開・下書きとして扱わない。

公開DocsでDataリンクを解決するときも匿名閲覧権限を適用する。編集者の認証情報を使って非公開Dataのタイトルや本文を公開画面へ持ち込まない。削除済み・非公開・解決不能な参照は、未取得のタイトルを補完せず、遷移できない中立な表示にする。本文に編集者が明示入力した文章は通常の公開本文として扱う。

最初のData選択UIは同じRepo内を対象とする。別RepoのDataへ拡張する場合も、DocsではそのRepoの匿名公開可否を確認し、公開記事に解決できない場合に認証必須のLibrary画面へ自動転送しない。Repoの非公開化は記事・ナビ・参照メタデータのすべてに適用する。

### 5. 取得とナビゲーション

セクション生成にはRepo全体の記事ID・タイトル・対象Property値を使用する。本文一覧の最初のページだけから構成を作らない。サーバーは匿名公開範囲で軽量なナビモデルを返し、本文は記事を開いたときに取得する。

タイトル検索もRepo全体を対象とし、検索結果には所属セクションを表示する。前後の記事はセクション順・記事順を平坦化して決める。取得上限やページングはDDで定義し、未取得の記事を検索済みと扱わない。

モバイルでは同じ構成を開閉式ナビに表示し、記事選択後に閉じて本文へフォーカスを移す。表示中の記事が属するセクションは自動展開する。折りたたみ操作はProperty値を変更しない。

## Consequences

通常のData分類がそのままDocsのセクションになる。トップや記事の案内もBlockNote本文で編集でき、本文とナビ構成の二重管理を減らせる。同じDataリンクをLibrary・Docsで使える。

一方、Selectの分類変更はDocsの構成にも反映される。Data参照のBlockNote schema、コンテキストに応じたURL解決、公開範囲内でのタイトル取得、参照失敗表示が必要になる。リンク形式追加時には既存本文とエクスポートの互換性を確認する。

## Alternatives Considered

| 案 | 評価 |
| --- | --- |
| Repo設定にsections/dataIdsを保存 | Propertyによる分類と所属記事が二重管理になるため採らない |
| トップのおすすめカードを専用設定で管理 | 本文のDataリンクと重なるため初期段階では設けない |
| 本文にDocs URLを固定保存 | Libraryで閲覧してもDocsへ移動し、表示先への依存が残るため採らない |
| 編集画面URLをDocs表示時に文字列置換 | URL形式依存であり、Data参照と通常URLを区別できないため採らない |
| 独立したDocs記事DBを作る | 本文・分類・権限の二重管理になるため採らない |

## Follow-up

この方針への合意後、DDで以下を確定して実装PRへ進む。

- トップ用Data IDとセクション用Property IDの保存場所・設定権限。
- Select選択肢の順序、記事の既定順、未分類の扱いとナビAPIの取得上限。
- BlockNoteのData検索・挿入UI、参照schema、Library/Docsそれぞれのリンク解決契約。
- リンク参照の一括取得、削除・改名・非公開化、既存本文とエクスポートの互換性。

受け入れ条件は、Property値を変えるだけでセクションが変わること、同じ本文のDataリンクがLibraryとDocsそれぞれのData画面へ遷移すること、2ページ目以降の記事も対象になること、匿名閲覧で非公開情報を取得しないこと、PC・モバイル・キーボードで操作できることとする。
