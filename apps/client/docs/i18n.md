# 多言語化（i18n）

v2 クライアントの UI 文言はすべて `src/i18n/` のカタログに入っています。
コンポーネントに英語のリテラルを直接書かないでください。

| レイヤー | 実装 |
|---|---|
| 対応ロケールと検出 | [`src/i18n/locales.ts`](../src/i18n/locales.ts) |
| カタログの読み込み・置換・複数形 | [`src/i18n/translate.ts`](../src/i18n/translate.ts) |
| `Intl` 由来の日付・数値・相対時刻・照合 | [`src/i18n/format.ts`](../src/i18n/format.ts) |
| React Provider と `useI18n()` / `useT()` | [`src/i18n/I18nContext.tsx`](../src/i18n/I18nContext.tsx) |
| 言語切替 UI（アカウントメニュー内） | [`src/components/LanguageMenuSection.tsx`](../src/components/LanguageMenuSection.tsx) |
| 文言カタログ | [`src/i18n/messages/`](../src/i18n/messages/) |
| macOS ネイティブメニューバー | [`src-tauri/src/macos_menu.rs`](../src-tauri/src/macos_menu.rs) / [`src/lib/desktop/menuLabels.ts`](../src/lib/desktop/menuLabels.ts) |

## 対応言語

英語 (`en`) が原文です。ほかに 日本語 / 简体中文 / 繁體中文 / 한국어 /
Español / Français / Deutsch / Português (Brasil) / Italiano / Русский の
10 言語を同梱しています。すべて左横書き（LTR）です。
アラビア語・ヘブライ語などの RTL 言語は、レイアウトの論理プロパティ対応が
別途必要なので、まだ入れていません。

## 使い方

```tsx
import { useI18n } from '../i18n'

function Example({ count }: { count: number }) {
  const { t, tPlural, formatDate } = useI18n()
  return (
    <>
      <h1>{t('home.title')}</h1>
      <p>{t('sidebar.repositories.actionsFor', { name: 'acme/docs' })}</p>
      <p>{tPlural('table.rowCount', count)}</p>
      <time>{formatDate(record.updatedAt, { dateStyle: 'medium' })}</time>
    </>
  )
}
```

React の外（API クライアント、Yjs ヘルパー、Tauri のタブ名など）からは、
表示中のロケールに束縛された `t` / `tPlural` を直接呼べます。

```ts
import { t } from '../i18n'

throw new RecordApiError(t('errors.dataNotFound'), 404)
```

`statusConfig` や `RECORD_PROPERTIES` のような定数テーブルは、文字列ではなく
`labelKey: MessageKey` を持ちます。描画時に `t(config.labelKey)` で解決するので、
言語を切り替えるとレコードを作り直さずにラベルだけが変わります。

## 文言を追加する

1. `messages/en.ts` にキーを足す。キーは画面ごとのドット区切り
   （`repoSettings.addProperty`）で、値の中の `{placeholder}` 名は
   全言語で共通にする。
2. 残り 10 言語のカタログに同じキーを足す。カタログは
   `LocaleMessages`（＝ `en` の全キー必須）で型付けしてあるので、
   抜けは `npm run type-check` で落ちます。
3. `npm test -- src/i18n` を流す。キーの過不足、`{placeholder}` の不一致、
   空文字は [`src/i18n/catalogs.test.ts`](../src/i18n/catalogs.test.ts) が弾きます。

## 複数形

`Intl.PluralRules` のカテゴリをキーの末尾に付けます。

```ts
'table.rowCount.one': '{count} data',
'table.rowCount.other': '{count} data',
```

`tPlural('table.rowCount', n)` が `one` / `few` / `many` / `other` から選び、
その言語にないカテゴリは `other` に落ちます。ロシア語のように英語より
カテゴリが多い言語は、`.few` / `.many` を自分のカタログにだけ足せます
（英語側に足す必要はありません）。

## 起動時のロケール決定

1. `localStorage` に保存された明示的な選択（`library-client-locale`）
2. `navigator.languages` を上から順に照合（`zh-TW` → `zh-Hant`、
   `en-GB` → `en` のように、細かい方から丸めます）
3. どれにも当たらなければ `en`

`main.tsx` は最初の描画前に `preloadInitialLocale()` を待つので、
英語が一瞬見えてから切り替わる、という挙動にはなりません。
`en` 以外のカタログは動的 import で分割されているため、
初回バンドルには読み込む 1 言語ぶんしか入りません。

## macOS のネイティブメニューバー

**macOS はメニューバーを翻訳してくれません。** `About …` / `Services` / `Edit` /
`Window` といった「標準」項目も、Tauri のメニューライブラリ（muda）が持つ英語
リテラルです。バンドルに `.lproj` を同梱していないので、アプリが持つ
`File ▸ New Tab` と `Library ▸ Check for Updates…` と事情は変わりません。
OS が用意するのは Services サブメニューの**中身**と、Window メニューに並ぶ
開いているウインドウの一覧だけです。

メニューは frontend がロケールを決めるより先に Rust で組み立てられるので、
原文である英語で組んでおき、カタログが読めた時点で frontend から翻訳済みラベルを
push します。

```
macos_menu::build（英語で組む・全項目のハンドルを保持）
  → NativeMenuLabels（I18nProvider の中）
  → menuLabels(t, productName)
  → invoke('set_menu_labels')
  → MenuHandles::apply（set_text で貼り替え）
```

`NativeMenuLabels` は `useI18n().t` の同一性で再実行するので、言語を切り替えた
ときはもちろん、遅れて到着したカタログでもメニューが貼り替わります。再起動は
要りません。

項目を足すときは `menuBar.*` にキーを足し、`MenuLabels` を **3 か所**
（`macos_menu.rs` の struct、`menuLabels.ts` の interface、`menuLabels()` の本体）
に揃えます。名前が食い違うとコマンド自体が失敗するので、英語のまま黙って残る
ことはありません。

`menuBar.*` だけは Apple がそのプラットフォームで使っている語と大文字小文字に
合わせています（英語は `Select All`、ドイツ語の File は `Ablage`）。カタログ全体の
sentence case とは揃いませんが、ネイティブのメニューバーとしてはそちらが正です。

## 翻訳しないもの

- プロダクト名（`Library`、`Library Chat`、`Cloud Engine`）
- 例示用の識別子（`ci-pipeline`、`research-library`、`database_…`）
- ユーザーが入力した値と、保存済みのデータ
- 既定のビュー名（`Table` / `Board` / `Workflow`）と
  `docs.defaultTitle`（`Untitled doc`）。これらは Yjs / PGlite に保存され
  共同編集者と共有される **データ** なので、閲覧者ごとに文言を変えると
  同じビューが人によって違う名前で見えることになります。
