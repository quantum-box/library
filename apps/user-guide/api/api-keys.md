# API キーの発行と失効

API キーは **組織 (organization) 単位** で発行されます。組織の中のどのリポジトリを
読み書きできるかは、組織に設定された権限に従います。リポジトリごとに別のキーが
発行されるわけではありません。

## 発行する

1. Web 画面で対象組織のリポジトリを開きます
2. 上部タブの **API** を選びます
3. クイックスタート「① API キーを作成」の **API キーを作成** を押します
4. キーの名前を入力します（例: `ci-pipeline`, `analytics-batch`）
5. 表示されたキーをコピーして保存します

::: warning キーは一度しか表示されません
発行直後のダイアログを閉じると、キーの値は二度と表示できません。控えを取り損ねた
場合は、そのキーを失効させて発行し直してください。
:::

キーの値は `pk_` で始まる文字列です。

## 保存する

キーはパスワードと同じ扱いをしてください。

- 環境変数やシークレットマネージャに置く（例: `LIBRARY_API_KEY`）
- リポジトリにコミットしない
- ブラウザで動くフロントエンドのコードに埋め込まない — 閲覧者に見えてしまいます
- 用途ごとに別のキーを発行する — 失効させたときの影響範囲が狭くなります

## 一覧する

**API** タブの「API キー管理」に、その組織で発行済みのキーが並びます。表示されるのは
名前・ID・作成日時で、キーの値は表示されません。

## 失効させる

一覧の各行の **失効** を押します。確認ダイアログで実行すると、そのキーはただちに
認証されなくなります。取り消しはできません。

次のような場合は失効させてください。

- キーが外部に漏れた、または漏れた可能性がある
- キーを使っていた連携を停止した
- 発行直後にキーの控えを取り損ねた

::: tip 稼働中の連携を止めずに入れ替える
先に新しいキーを発行して連携先の設定を更新し、切り替えが終わってから古いキーを
失効させると、停止時間なく入れ替えられます。
:::

## 権限

キーを発行・一覧・失効するには、組織に対する権限が必要です。

| 操作 | 必要な権限 |
| --- | --- |
| 発行 | `library:CreateApiKey` |
| 一覧 | `library:ListApiKeys` |
| 失効 | `library:RevokeApiKey` |

標準の `library:member` および `library:admin` ロールには、いずれの権限も
含まれています。権限がない場合、画面上の操作は「権限がありません」というエラーに
なります。

## サービスアカウントとの関係

発行されたキーは、組織の `default` サービスアカウントに紐づきます。キーで送った
リクエストは、そのサービスアカウントとして実行されます。ユーザーとして実行される
わけではないため、監査ログ上もサービスアカウントとして記録されます。
